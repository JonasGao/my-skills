你正在执行 `/planning`，职责是调用 Claude Code 原生计划模式，调查现状并产出待批准的实施计划。

## 用户输入

命令后的文本是本次计划的目标、任务描述或约束。文本为空时，使用当前会话上下文确定目标。

> $ARGUMENTS

## 执行流程

1. **进入原生计划模式**：立即调用 `EnterPlanMode`。在该调用成功前，不调查、不输出计划，也不执行实现工作。
2. **确定目标**：在原生计划模式内合并用户输入和当前会话上下文，写出一句可验证的目标。目标不明确时，在计划模式内提出最少的澄清问题。
3. **调查现状**：在计划模式内读取相关目录、实现、配置、测试和项目约定；必要时查看只读 Git 信息。以代码和配置中的事实为依据，不凭空补全。
4. **委托计划型调查**：需要并行调查或独立设计时，可使用 `Agent` 工具并将 `subagent_type` 设为 Claude Code 内置的 `Plan`。它会返回计划型分析供当前 agent 汇总；不要让子 agent 修改项目文件。Claude Code 的 `Agent` 参数没有独立的 `permissionMode`，因此不要声称子 agent 开启了独立的原生计划模式或计划审批界面。最终计划仍由当前会话写入原生计划文件并通过 `ExitPlanMode` 展示。
5. **界定改动**：在计划模式内列出需要修改、新增或删除的文件，说明模块关系、约束、风险和验证方式。
6. **设计方案**：在计划模式内选择与现有架构一致的实现路径。存在真实取舍时，列出方案 A / 方案 B 及推荐理由；没有取舍时只给一个方案。
7. **写入原生计划**：在计划模式内将完整计划写入原生计划文件。计划至少包含总览、详细步骤、完成标准、依赖、风险和待确认问题；每一步都必须可验证。
8. **展示并请求批准**：计划完成后调用 `ExitPlanMode`，交给 Claude Code 原生计划界面展示和请求用户批准。不要在命令正文中自行模拟计划审批，也不要在退出计划模式前执行实现工作。

## 只读边界

- 使用读取、搜索和只读 Git 操作调查项目。
- 子 agent 只用于调查和设计；委托时优先使用 `subagent_type: Plan`，不得让其执行实现工作。子 agent 返回的分析由当前会话整合进原生计划，不等同于子 agent 自己的原生计划界面。
- 只允许原生计划模式工具写入计划文件；不修改项目文件、数据库、依赖、Git 状态或其他外部状态。
- 仅在答案会改变目标、范围或方案时，通过 `AskUserQuestion` 澄清；计划审批由 `ExitPlanMode` 处理。
- 不把推测写成事实；缺少证据时标记为待确认，并说明需要查看的来源或需要用户决定的事项。

## 原生计划内容

### 总览

> 目标：一句话 ｜ 步骤：N 步 ｜ 风险：低 / 中 / 高

### 详细步骤

计划文件按顺序编号。每步包含：

- **目标**：要完成的工作
- **涉及文件**：具体路径；若尚未确定，写出调查范围
- **完成标准**：可检查的结果
- **依赖**：前置步骤或外部条件；没有则写“无”

在关键路径前标注 `⚠️`，在风险前标注 `🔴`。需要用户选择的内容集中放在下一节。

### 待确认问题

只列出会改变方案或边界的问题；没有则写“无”。
